The chain

On COCO weights ball_ids resolves to an empty list. So ball_xy is always None. So the possession block, which sits inside if ball_xy is not None, never executes. So possession_pct is always None.

That is not a model that performs badly. It is a feature that has never run once — and it looked fine, because the pipeline completed without error every time.

The pattern, for the third time

A silent failure that produces plausible output. Traffic Lens had five. This project has its own: a dead code path, and a calibration that cannot report its own error. The fix in both cases was never cleverer code — it was having something to check against.

Two datasets, two different jobs

They are not alternatives. Roboflow fixes what the pipeline can see; SoccerNet fixes what you can claim. Do them in that order — detection first because it is cheap and unblocks features, measurement second because it is what makes the rest defensible.

§01

SoccerNet — what you can measure

A research dataset built for exactly this domain. The reason it matters here is narrow: it ships ground-truth tracks and annotated field geometry. Those are the two things this project has been substituting proxies for.

SoccerNet-Tracking

What it is
Scale200 sequences of 30 s, 225,375 annotated frames, plus a 45-minute halftime video for long-term tracking
AnnotationsPer-frame boxes with persistent identities — the thing you cannot derive from your own footage
Reported metricsHOTA, with its DetA and AssA components

The number worth sitting with

Published state of the art on that benchmark, where the methods were given oracle detections by the dataset — perfect boxes, free:

HOTA
√(DetA × AssA)

Hand a state-of-the-art tracker flawless boxes and more than a quarter of the association work is still wrong. Players on a team look alike, the camera pans constantly, bodies occlude each other every few seconds.

Check it yourself

√(0.99236 × 0.73567) = 0.85443, against a reported HOTA of 85.443. The geometric-mean relationship reproduces the benchmark number to five decimals — it is the definition, not an approximation being offered to you.

This reframes the roadmap. The open items were "fine-tune a detector" and "add ball tracking", both detection work. The benchmark says the ceiling is on the association side — re-identification, motion models through occlusion, the second association pass.

SoccerNet-Calibration

22,816 images with every visible field segment annotated — lines, circle arcs, goalposts — as polylines, processed geometrically into 57 keypoints including the tangent points of the centre-circle ellipse.

What that changes is not the homography. It is that the fit becomes over-determined. Four points give exactly eight equations for eight unknowns, so the residual is zero however badly you placed them — there is no signal in it. A fifth point lets the system disagree with itself, and that disagreement is the error estimate you never had.

The honest costs
  • Access requires agreeing to terms — check the current conditions yourself rather than trusting a summary, including whether your intended use is covered.
  • It is large. Plan storage and start with a subset.
  • MOT-format conversion, and use TrackEval rather than reimplementing metrics that have edge cases you don't want to rediscover.
  • A benchmark number is a commitment: once you can be compared, you will be. That is the entire value.

The full argument, with four interactive figures, is in Ground truth.

§02

Roboflow — what the pipeline can see

The football-players-detection set labels four classes: ball, player, goalkeeper, referee, with pretrained YOLOv8/v9/v11 and RF-DETR checkpoints available. It is small, immediate, and it unblocks the most.

Three things it fixes

TodayWith four classes
Possession — never computed. ball_ids is empty, so the block never executes. A real number, for the first time.
Keepers & referees — forced into an outfield team. k=2 cannot represent four kits. Detected as their own classes, removed from clustering entirely.
The ball — COCO's sports ball, trained on large, centred, unblurred balls. A purpose-labelled class trained on ~10 px motion-blurred footballs.
Parameter fix vs structural fix

Worth naming, because the distinction recurs. Raising k from 2 to 4 is a parameter fix: it makes a wrong model less wrong, and leaves you with four unlabelled clusters and no way to know which two are the teams.

Detecting keepers and referees as classes is a structural fix: it changes what enters the clustering, so k=2 becomes the right model for what remains. No hyperparameter value could have achieved that.

Read per class, always

The m in mAP is "mean over classes", and it is where the most common misreading lives. Ball detection will be dramatically worse than player detection — roughly 10 px against 200 px — and a single averaged number hides exactly the failure you most need to see. If the headline looks respectable it is being carried by player, which is most of the boxes.

finetune_detector.ipynb trains at imgsz=1280 rather than 640 for the same reason the pipeline infers at 1280: at 640 the ball is gone before the model sees it.

Verify before you train

§2 of the notebook prints the class-index mapping and asserts that player, ball and referee all resolve by name. A class index only means something relative to the model that produced it — index 0 is person in COCO and almost certainly ball here. That check costs seconds, and it is exactly the one that would have saved Traffic Lens an entire run.

Architecture — before and after

Why there is no job queue

RunPod Serverless already is one. POST /run returns a job id immediately and GET /status/{id} reports progress, so there is no queue, no worker pool and no job table to build. The control plane exists only because a client cannot hold the RunPod key or the storage credentials — it hands out short-lived HMAC URLs binding key, method and expiry, so a URL minted for reading cannot be replayed to write.

Why this ordering

Roboflow first. A small dataset, an hour of GPU, and it turns two dead features on. It also removes the goalkeeper problem structurally rather than papering over it.

SoccerNet second. It is the step that converts "the tracking looks good" into a number a stranger can check — but it is a larger lift, and it is worth less before the detector can actually see the objects being tracked.

Still open, and stated rather than buried
  • The pipeline has still never completed an end-to-end run. Everything above is unverified until it does.
  • Calibration keypoints are hand-authored JSON. There is no picker and no auto-detection.
  • The homography is fitted once and reused for the clip — fine for broadcast, silently wrong handheld.
  • The service has no auth. Max workers = 2 is currently the only thing bounding spend.
