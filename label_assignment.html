Companion note · detection internals

Label assignment: why anchors and NMS both disappeared

Two changes people usually learn as separate architectural facts are really one decision, made twice. This walks through what the detection head emits, how ground truth gets matched to predictions, and why changing that matching removed a hand-tuned post-processing step from inference entirely.

§01

One question explains both changes

Here is the question that anchors everything below:

During training, how many predictions is each ground-truth object allowed to claim?

Every detector has to answer it. A detection head emits thousands of candidate predictions per image — for a 640×640 input at strides 8, 16 and 32, that's 80² + 40² + 20² = 8,400 slots. Exactly one or two of them correspond to a real object. The rest must learn to say "nothing here."

Deciding which slots are responsible for which object is label assignment. It's not part of the network and it doesn't exist at inference — it's purely a training-time bookkeeping rule. And it turns out to determine both of the things you asked about:

GenerationPredictions per objectConsequence at inference
YOLOv3–v5 anchor-basedMany (every anchor above an IoU threshold)Duplicate boxes → NMS required
YOLOv8 anchor-freeMany (dynamic top-k)Duplicate boxes → NMS still required
YOLOv10 / YOLO26Exactly oneNo duplicates → no NMS

Note the middle row. Dropping anchors and dropping NMS are independent changes — v8 removed anchors and still needed NMS, because it was still handing each object many positives. They're related only in that both are governed by assignment.

§02

What changed first: how a box is described

Before assignment, the smaller change — how a prediction slot expresses a box at all.

Anchor-based. Each grid cell carries a few anchor boxes: fixed width/height templates obtained by k-means clustering the training set's box dimensions. The network never predicts a box directly; it predicts a correction to a template. Width comes out as an exponential scaling of the anchor's width, so the anchor sets the ballpark and the network nudges it.

Anchor-free. The template is gone. Each grid point predicts four numbers directly: the distance from that point to the box's left, top, right and bottom edges. Nothing dataset-specific is baked in.

This is why anchors were dropped in v8. They were dataset-specific hyperparameters that had to be re-clustered for a new domain, and they multiplied the number of prediction slots by the number of templates. Removing them made the head simpler and the model more portable — but it did nothing about duplicate detections, because assignment was still one-to-many.

Aside: DFL, and why YOLO26 removed it

YOLOv8 didn't regress each distance as a plain number. It predicted a probability distribution over discretised distance bins and took the expectation — Distribution Focal Loss. The idea is that a distribution expresses uncertainty about an ambiguous edge better than a single value.

distance = Σ i · softmax(logits)ᵢ i = 0 … reg_max−1

The cost is a wider head (each edge needs reg_max channels instead of 1) and a bounded range — you cannot predict a distance beyond the largest bin.

Per the Ultralytics YOLO26 documentation, YOLO26 removes DFL, "reducing detection-head complexity while preserving an unconstrained regression range." Fewer channels, no bin ceiling, simpler export.

§03

Assignment, three ways — the interactive answer

Now the main event. Below is a feature grid over an object. Each cell centre is one prediction slot. The assignment rule decides which slots become positives — the ones trained to output this object — and which are pushed toward "background".

Switch between the three rules and watch the positive count, then look at what each produces at inference.

What each rule actually computes

1 · Static IoU threshold (anchor era). Geometry only. Compute IoU between every anchor box and the ground truth; every anchor above ~0.5 becomes a positive. The model's own opinion is irrelevant — the same cells are chosen at epoch 1 and epoch 300.

2 · Dynamic top-k (YOLOv8's task-aligned assigner). Score each candidate by how well it's already doing on both tasks at once — classification confidence and box overlap — then take the best k:

t = s^α · IoU^β s = predicted class score for the GT's class IoU = overlap of predicted box with the GT α, β weight the two terms (YOLOv8 defaults: α = 0.5, β = 6)

Two consequences worth understanding. It's task-aligned: a cell that localises well but classifies badly isn't chosen, so the two heads are pushed to agree. And it's dynamic: the assignment depends on the model's current predictions, so it co-evolves with training instead of being fixed by geometry.

3 · One-to-one. Same metric, k = 1. Only the single best-aligned slot is a positive; every other slot — including ones with 0.9 IoU — is trained as background. That's the whole mechanism, and it's the direct answer to your first question: the "matching" is an argmax over an alignment score, not a separate algorithm.

Where the Hungarian algorithm comes in

With one object, one-to-one is just an argmax. With several objects it becomes a genuine assignment problem: two players standing close together might both rank the same slot highest, and each slot can serve only one object.

That's a bipartite matching problem — minimise total cost across a predictions × objects cost matrix, subject to each object getting exactly one prediction. The Hungarian algorithm solves it optimally in polynomial time, and it's what DETR uses. Greedy argmax can be provably worse: taking the locally best pair first can force a bad choice later.

§04

Why one-to-one alone doesn't train well

If one-to-one removes NMS, why not use it from the start? Because it starves the model of gradient.

With top-k, one object produces ten positive slots — ten chances per object per image to learn "this looks like a player, and the box is about here." With one-to-one you get one. Training is slower and final accuracy is worse; the supervision signal is simply thinner.

The resolution is to do both. YOLOv10 introduced consistent dual assignments: two heads on a shared backbone and neck. A one-to-many head supplies rich gradients during training. A one-to-one head learns to produce exactly one box. At inference the one-to-many head is discarded entirely, so only the clean single-box head runs.

The word consistent is carrying weight. Both heads use the same alignment metric with the same α and β, so the slot the one-to-one head considers best tends to also sit inside the one-to-many head's top-k. If the two used different metrics, the shared backbone would receive conflicting supervision — optimised toward one set of slots while the deployed head reads a different one. Aligning them is what lets the o2o head inherit the o2m head's learning rather than fight it.

YOLO26 continues this line. Its documentation describes ProgLoss, which progressively "shift[s] supervision toward the inference-time head" over training — start with the dense signal, end weighted toward the head you'll actually deploy — and STAL (Small-Target-Aware Label assignment), which "maintain[s] positive label coverage for small objects," addressing a real weakness of strict one-to-one: tiny objects win few slots to begin with, and giving them exactly one is fragile.

Why this matters for the ball

That last point is directly relevant to the soccer project. A football is exactly the case STAL targets — a handful of pixels, few candidate slots, and under strict one-to-one it gets one positive per image against thousands of negatives. If ball detection underperforms, assignment is a plausible cause and not only resolution.

§05

NMS, the step that's now gone

For completeness — what the removed step was actually doing. Given many overlapping boxes, sort by confidence, keep the best, delete everything overlapping it beyond an IoU threshold, repeat.

Three costs, which together explain why removing it was worth architectural effort:

  • A hyperparameter you must tune per domain. Crowded scenes — a defensive wall, a ruck, a packed car park — are exactly where the right threshold is least obvious and the errors most costly.
  • Sequential and CPU-bound. The sort-and-suppress loop parallelises poorly, so it becomes a latency floor that GPU speedups can't touch. Removing it cut YOLOv10-S end-to-end latency by 4.63 ms.
  • Outside the network. Training optimised the model; a hand-tuned loop decided the final output. What you trained wasn't quite what you deployed.
§06

The summary you'd give in an interview

Anchors and NMS were removed by two separate changes to label assignment, several versions apart.

Anchors went first (v8): instead of predicting corrections to clustered template boxes, each grid point regresses four edge distances directly, and assignment became dynamic and task-aligned — scoring candidates by s^α · IoU^β against the model's own current predictions rather than by fixed geometry. That removed a set of dataset-specific hyperparameters, but each object still claimed k slots, so duplicates and NMS remained.

NMS went later (v10, and default in YOLO26): assignment became one-to-one, so each object trains exactly one slot and the network stops emitting duplicates at all. Because a lone one-to-one signal trains poorly, it's paired with a one-to-many head during training and that head is dropped at inference — consistent dual assignment. The result is genuinely end-to-end: image in, final boxes out.

And the through-line worth saying out loud: both changes moved work out of hand-tuned post-processing and into what the network is taught. That's the same instinct behind every other "end-to-end" move in deep learning.
